# 🤖 COMPORTEMENT ATTENDU À LA FIN

L'objectif final est que Claude puisse interagir avec mon Issue Tracker de manière sécurisée.

Exemple :

> "Crée une issue dans le projet X pour ce bug et assigne-la à Y."

Claude doit pouvoir :

1. Identifier ou rechercher le bon projet.
2. Vérifier les utilisateurs/membres valides.
3. Vérifier qu'une issue similaire n'existe pas déjà si nécessaire.
4. Appeler l'outil MCP approprié.
5. Utiliser la vraie logique métier de mon backend.
6. Créer l'issue correctement.

Autre exemple :

> "Commence à travailler sur l'issue ISSUE-42."

Claude peut consulter l'issue puis demander/exécuter le changement de statut selon les règles du système :

```text
OPEN → IN_PROGRESS
```

Mais les transitions doivent respecter les règles réelles de mon application.
